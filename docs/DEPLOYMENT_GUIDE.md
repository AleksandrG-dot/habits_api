
# Deployment Guide

Данный документ описывает процесс подготовки сервера и деплоя backend‑сервиса **Habits API**.
Он предназначен как операционная инструкция (админ-гайд) и может использоваться
как памятка для повторного развёртывания проекта.

Документ актуален для ветки `main_with_CI-CD`.

---

## 1. Общая схема деплоя

Процесс развёртывания проекта состоит из двух этапов:

1. **Первичный (ручной) деплой**
   - Подготовка сервера
   - Установка необходимых зависимостей
   - Первый запуск контейнеров

2. **Автоматический деплой**
   - Выполняется через GitHub Actions
   - Запускается автоматически при push в репозиторий
   - Не требует ручного вмешательства

---

## 2. Требования к серверу

- Linux (Ubuntu 20.04+)
- Установленный Docker
- Установленный Docker Compose
- Открытые порты:
  - 80, 443, 22 (backend / reverse proxy при необходимости)
- Доступ по SSH (открыт порт 22)

---

## 3. Первичная настройка сервера

### 3.1 Создание сервера на базе Ubuntu, поддерживающем SSH протокол

### 3.2 Подключение к серверу командой в терминале  
`ssh <user_name>@<your_server_ip>`

### 3.3 Выполнение обновления ПО на сервере (по необходимости)  
```bash
sudo apt update && sudo apt upgrade
```

### 3.4 Настройка firewall (UFW) (рекомендуемая конфигурация)
Для базовой защиты сервера рекомендуется настроить firewall и оставить открытыми только порты 22, 80, 443.  
**Внимание!** Выбирайте настройку в зависимости от Вашей политики безопасности.

```commandline
sudo ufw allow 80/tcp  
sudo ufw allow 443/tcp  
sudo ufw allow 22/tcp  
sudo ufw enable
```

Проверка статуса 
```bash
sudo ufw status
```

### 3.5 Создайте директорию где будет храниться проект командой `mkdir <directory>`

### 3.6 Перейдите в неё командой `cd <directory>`

### 3.7 Настройте сервер с Docker по инструкции
https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository

### 3.8 Установите docker compose и git:
```commandline
sudo apt update
sudo apt install docker-compose
sudo apt install git
sudo apt upgrade
```

Проверка установки
```bash
docker --version
docker-compose --version
```

*В зависимости от версии Docker может использоваться `docker compose`.

## 4. Подготовка проекта на сервере

1. Клонировать репозиторий:

```bash
git clone https://github.com/AleksandrG-dot/habits_api.git
cd habits_api
git checkout main_with_CI-CD
```

2. Создать файл окружения `.env` на основе примера `.env.example` в корне проекта:
```bash
cp .env.example .env
```
Затем отредактируйте его командой `nano .env`, добавив свои значения.

---

## 5. Первичный деплой (ручной)

Выполнить сборку и запуск контейнеров. Затраченное время около 1-5 минут в зависимости от скорости интернет вашего сервера:

```bash
docker-compose up --build -d
```

Проверить, что контейнеры запущены `docker ps -a` или 
```bash
docker-compose ps
```

После успешного запуска сервис становится доступен на сервере.

Для создания суперпользователя воспользуйтесь командой:  
`docker-compose exec habits_api python manage.py createadmin`

---

## 6. Настройка CI/CD

### 6.1 GitHub Secrets

Для работы CI/CD в репозитории должны быть добавлены следующие Secrets:

- `DOCKER_HUB_USERNAME`
- `DOCKER_HUB_ACCESS_TOKEN`
- `SERVER_IP`
- `SSH_USER`
- `SSH_KEY`

### 6.2 Workflow

CI/CD pipeline реализован с использованием GitHub Actions и выполняет:

- запуск тестов;
- линтинг кода;
- сборку Docker-образов;
- публикацию образов в DockerHub;
- деплой на сервер через SSH и Docker Compose.

---

## 7. Автоматический деплой

После первичной настройки сервера и CI/CD:

1. Разработчик выполняет push изменений в репозиторий или pull request.
2. GitHub Actions автоматически запускает workflow.
3. При успешном прохождении всех этапов контейнеры на сервере обновляются.
4. Новая версия приложения становится доступной без ручного вмешательства.

---

## 8. Примечания

- Первый деплой всегда выполняется вручную.
- Все последующие обновления происходят автоматически.
- Документ не является техническим заданием и дополняет его.
